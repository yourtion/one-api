# 稳定性修复与 Phase 7 收尾

> 用户要求：先修复已复现问题，再完成 Phase 7。
> 基线：`phase7-serve-distribution` / `37e4582`；构建通过、379 个既有测试通过。

## 修复范围

1. 关键词搜索的 OR 子句必须整体与字段过滤 AND 组合，列表与总数一致。
2. 新建模型、追加字段及刷新结构保留逻辑类型、标签、枚举、隐藏和只读标记；物理类型真实变化时不得保留不兼容逻辑类型。导入既有表继续使用结构推断。
3. 所有入口通过 engine 执行字段白名单与类型校验。新增区分必填、可空、默认值、自增和系统时间戳；更新按补丁校验。布尔值正确转换为 SQLite 可存储值；业务错误使用共享错误工厂。
4. CSV 导出在保留查询条件的前提下导出最多 10000 行，不受普通分页 100 行上限影响；只有真正超限才发截断提示。
5. 待改密管理员仅可查看自身、修改密码和登出；管理功能必须由服务端拦截。修改为相同密码不能解除强制改密状态。
6. CI 执行覆盖率；core 行与分支门槛保持 90% / 85%，补针对性测试，不放宽或扩大排除范围。

## Phase 7 验收

- 沿用既有三层分发设计：可发包 server、静态 web、薄壳 serve。
- CLI 参数与环境变量优先级明确，非法端口和缺失参数在启动前报错。
- 默认启用已安装的 web，显式 `--no-web` 必须禁用；未安装 web 时可正常提供 API。
- `createServer` 启动失败也释放已创建资源；关闭幂等，信号处理只由入口负责。
- 冒烟测试使用随机端口、当前 Node 可执行文件、严格 HTTP 断言及有界进程清理。
- 包运行时要求与实际依赖一致；准备真实发布包，在仓库外干净安装并启动验证。
- 保留仅本地发布的既有决定；发布脚本先完成质量门，不增加 CI 自动发布。
- 实现完成后分别记录代码、包验证和 npm 发布状态，不用本地冒烟代替实际发布结论。

## 不在本次范围

MySQL、多租户、索引管理、批量业务接口及其他产品扩展。
